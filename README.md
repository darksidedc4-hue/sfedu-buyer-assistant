# ИИ-помощник покупателя (team-03)

Решение кейса хакатона ЮФУ, контракт версии 1.1. Помощник читает диалог с покупателем, уточняет недостающие условия
и подбирает комплект из каталога: по одному товару каждой названной категории, в одном городе, в пределах общего бюджета.

## Установка

Нужен только Python 3.9 или новее и bash. Сторонних библиотек нет, ставить нечего (`requirements.txt` пуст).

```sh
chmod +x run
```

## Настройка доступа к модели

Подключение читается из переменных окружения, значения можно подменить при проверке:

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL` | адрес API организаторов |
| `LLM_MODEL` | `google/gemma-4-31B-it` |
| `LLM_API_KEY` | ключ команды |
| `LLM_USER_AGENT` | имя клиента, по умолчанию `buyer-assistant/1.0` |

Для локальной работы можно положить те же строки в файл `.env` в корне (образец в `.env.example`). Переменные окружения
важнее файла. `.env` в Git не попадает.

## Запуск

```sh
./run --catalog /absolute/path/catalog.json < request.json > response.json
```

Один JSON из stdin, один JSON в stdout, логи в stderr. Код завершения 0 для статусов `ok`, `clarify`, `no_match`;
2 при нечитаемых входных данных; 3, если модель недоступна (сбой сервиса не выдаётся за `no_match`).

Открытые примеры:

```sh
./run --catalog "$PWD/data/catalog.json" < examples/01-selection/request.json
./run --catalog "$PWD/data/catalog.json" < examples/02-clarification/request.json
```

Диалог в консоли для показа:

```sh
python3 chat.py            # добавьте --json, чтобы видеть и сырой ответ по контракту
```

## Как помощник ведёт диалог

- Город и бюджет не подставляются: без них статус `clarify`, вопросы обо всём недостающем сразу. Если покупатель в
  ответ на вопрос о бюджете числа не назвал, вопрос повторяется с объяснением и ценой самого дешёвого комплекта.
- Прямые слова «бюджет не ограничен», «цена не важна» считаются решением покупателя: варианты идут от дешёвого.
- «Не нравится», «покажи другие» после показанных вариантов: предлагаются комплекты, которых ещё не показывали
  (что показано, видно из прошлых ответов помощника в `messages`); когда подходящие кончились, это `no_match`.
- «Хочу в другом городе» без названия города: вопрос, в каком.

## Как это устроено

```
диалог ──► Gemma: разбор условий в строгую структуру ──► проверка и перевод единиц ──► чего-то не хватает? ──► clarify
                                                                              │
                                    каталог ──► отбор по полям ──► комплекты ──┴──► ok (до 3 вариантов) или no_match
```

1. **Разбор запроса: языковая модель.** `assistant/extract.py` отправляет Gemma реплики диалога и справочник городов
   и получает JSON по схеме (`response_format: json_schema`, `strict: true`): категории, город, бюджет, ограничения
   ширины стола, цветовой температуры лампы и регулировки кресла. Модель учитывает всю историю: позднее условие
   заменяет раннее, короткий ответ («15 тысяч») относится к заданному вопросу. Числа она возвращает как сказано
   (значение, единица, вид сравнения), а в сантиметры и рубли их переводит код.
2. **Проверка разбора: код.** `extract.normalize` отбрасывает невозможные значения и превращает всё неизвестное в вопрос:
   нет категории или названа неподдерживаемая, города нет в справочнике или названо несколько, бюджет не назван или
   назван без числа. Значений по умолчанию нет.
3. **Подбор: код, без модели.** `assistant/picker.py` работает только по структурированным полям каталога:
   `category`, `city_id`, `price_rub`, `attributes`. Границы строгие и нестрогие различаются («не шире» и «уже»),
   отсутствующая характеристика при ограничении означает «не подходит», `false` и `0` считаются значениями.
   Итог считается суммой цен по каталогу и сравнивается с бюджетом (равенство допустимо).
4. **Ответ: код.** `assistant/reply.py` собирает объяснения из данных каталога: что за товары, их характеристики и цены,
   сколько остаётся от бюджета, какие условия соблюдены. При `no_match` называется препятствие (нет товара в городе,
   нет товара под ограничение и что есть на самом деле, не хватает бюджета и на сколько) и варианты, что изменить.

Модель вызывается один раз на запрос, обычно это 4–8 секунд. Предел API на вход (32 768 байт) соблюдается: длинные
реплики обрезаются по байтам. При ответах 429 и 5xx делается до двух повторов в пределах отведённого времени.

## Защита от манипуляций в объявлениях ★

Названия и описания объявлений в модель не передаются совсем, а подбор идёт только по структурированным полям.
Поэтому инструкция, вставленная в текст объявления, не может изменить ни условия покупателя, ни состав комплекта,
ни сумму. Подходящее по данным объявление при этом участвует в подборе и со вставкой. Название товара попадает
только в текст объяснения как цитата. Проверки: класс `Injection` в `tests/test_logic.py`.

## Сетевые зависимости

Единственное обращение в сеть: `POST {LLM_BASE_URL}/chat/completions`. Больше решение никуда не ходит.

## Проверка

```sh
python3 -m unittest discover -s tests     # без сети: правила подбора, разбор ответа модели, тексты, защита
python3 tests/live_scenarios.py           # 39 диалогов через настоящую модель, нужен ключ; идёт около трёх минут
python3 tests/contract_check.py           # ./run по пунктам контракта на своём каталоге из 250 объявлений с ловушками
```

`tests/live_scenarios.py` проверяет ответы независимо от кода подбора: условия каждого сценария заданы вручную,
комплекты перебираются в самом тесте.

`tests/contract_check.py` запускает `./run` как проверяющий: другой каталог (другие ID и цены, объявления без
характеристик, значения `false`, текст, расходящийся с полями, инструкции в описаниях), проверка кода выхода,
чистоты stdout, времени, структуры по `schemas/response.schema.json` (если установлен `jsonschema`) и смысла ответа,
плюс отрицательные случаи: нечитаемый вход и недоступная модель.

## Состав репозитория

| Путь | Что там |
|---|---|
| `run` | точка входа по контракту |
| `assistant/main.py` | чтение запроса и каталога, выбор статуса |
| `assistant/llm.py` | вызов API модели, повторы, ошибки |
| `assistant/extract.py` | инструкция модели, схема ответа, проверка разбора |
| `assistant/picker.py` | отбор объявлений и сборка комплектов |
| `assistant/reply.py` | тексты вопросов, объяснений и отказов |
| `chat.py` | диалог в консоли |
| `data/` | справочники городов и категорий, учебный каталог |
| `tests/` | проверки |
